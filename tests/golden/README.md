# tests/golden - verified real outputs, module by module

Each module's REAL output on the fixtures is saved here once verified, so
the NEXT module's tests consume verified real
data instead of hand-written samples. That gives every directory here one of two roles:

- **Test input**: loaded by the next module's test suite (a regression on these breaks tests
  directly).
- **Evidence-only**: consumed by no test as input; it is the committed proof of a verified
  run. These are pinned byte-for-byte by `EVIDENCE.sha256` and checked by
  `tests/test_evidence_goldens.py`, so silent regeneration cannot slip through. If you
  legitimately regenerate evidence, refresh the manifest (command in that test's docstring).

There is no `m3/`: M3 (translation gloss) is a deferred module. The one non-English
provision found so far ships via reviewed `config/verbatim_english.json` instead.

Why some directories carry markdown and most do not: `m11/EVAL.md` and `repro/REPORT.md`
are evaluation and run RECORDS that must travel with the artifacts they describe. The pure
test-input directories (m1-m8) intentionally carry no prose; their meaning is defined by
the tests that consume them and the generator scripts' docstrings.
